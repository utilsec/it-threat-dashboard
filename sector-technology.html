Citrix NetScaler: three zero-days exploited in a fortnight — two in CISA KEV since 27 September and a third since 4 October — with web shells, rogue admin accounts and stolen configurations left on appliances that patching alone does not clean

Citrix fixed eight NetScaler ADC and Gateway flaws in bulletin CTX697096 on 27 September, two of them already under attack, and CISA added both to the Known Exploited Vulnerabilities catalog the same day with a 30 September federal deadline. CVE-2026-88771 is an improper-input-validation flaw that lets an unauthenticated attacker run commands, and it affects default configurations; CVE-2026-88772 is a memory overflow that can lead to code execution or denial of service on appliances with DTLS enabled, which VPN virtual servers have by default. Both are rated CVSS v4 9.5. CISA said attackers were exploiting them globally and asked defenders to preserve forensic evidence before patching, because updating can destroy it; the Dutch NCSC said exploitation had been found at multiple Citrix customers worldwide. Exploitation broadened after watchTowr published a root-cause analysis on 28 September. Google Threat Intelligence Group and Mandiant describe “dozens” of victim organisations across government, education, technology, financial services, telecoms and legal services in North America and Europe, and attribute the activity only to suspected state-sponsored actors, naming no group; Arctic Wolf counts at least 78 organisations, and the researcher Kevin Beaumont, from his own tracking, more than 100. The activity traces back to early September, and Unit 42 puts the first signs at 21 August. Intruders left a PHP web shell called WHIPSHOT, a Python tunneller called SLAPSHOT and a rogue superuser account named sec_monitor, archived and took the appliance configuration in /flash/nsconfig, and tampered with logs; Mandiant’s CTO warned that upgrading alone neither removes that access nor deals with stolen credentials. On 3 October Citrix patched a third exploited flaw, CVE-2026-88779 (CVSS v4 8.7), a memory overflow on appliances configured as a SAML service provider or identity provider, saying it had seen targeted attacks that can cause denial of service and no impact on the integrity of customer data; CISA added it to KEV on 4 October with a 7 October deadline. watchTowr reproduced it as a crash-only bug and suspects it is being used to knock appliances over to speed up exploitation of CVE-2026-88771; Beaumont reported signs of code execution on a patched honeypot, a view watchTowr disputes. In the Netherlands, a ministry and hospitals took Citrix environments offline as a precaution; those were shutdowns, not confirmed compromises. It leads this page because it is an active campaign, with confirmed victims in the technology sector, against a product that is often the single front door for engineers’ remote access and single sign-on — and because a fully patched appliance can still hold an intruder.

Bitget: attackers took over two third-party security appliances inside the exchange and used them to reach its wallet servers — up to about $388 million taken on 25 September, and the appliance vendors are still unnamed

Mandiant’s status update, published by Bitget on 28 September, says the attackers obtained unauthorised privileged access to two unnamed third-party security appliances, which it calls A and B, installed a web shell and a command-and-control channel on appliance B, moved from there to Bitget’s production wallet job server and deployed malicious packages that gave them control of it. For technology companies the uncomfortable part is the entry point: the devices bought to protect the network were the foothold, and because the products are unnamed, nobody outside the investigation can yet check whether they run the same ones.

The Dutch Institute for Vulnerability Disclosure has published its case file on the breach it first announced on 24 September. The way in was a chain of two previously unknown flaws in the open-source Zammad helpdesk it ran: CVE-2026-102489, a session-fixation flaw that leads to code execution as the zammad user, and CVE-2026-102490, a local privilege escalation from that user to root. DIVD urges anyone running any version of Zammad to update to version 7 or take it offline, and has scanned for exposed instances to warn their owners. For technology and SaaS companies, Zammad is the kind of self-hosted support tool that sits outside the product security programme yet holds customer tickets and attachments.

Attackers made MemTensor’s own GitHub Actions release workflows hand over its npm and PyPI publish tokens — then shipped “sckit”, a cross-platform stealer built to copy itself into more packages and workflows

Four supply-chain security firms — Aikido, SafeDep, Socket and StepSecurity — reported on 23 September that the AI-agent memory project MemTensor was compromised through its own release automation. The attackers did not need a maintainer’s laptop or password: they pushed commits that caused MemTensor’s GitHub Actions release workflows to hand over the npm and PyPI publishing tokens, and used those tokens to publish malicious versions of @memtensor/memos-cloud-openclaw-plugin (0.1.21, 0.1.23 and 0.1.25) on npm and MemoryOS 2.0.34 on PyPI, which has since been quarantined. The payload, a Go implant the researchers call sckit, runs on Windows, Linux and macOS and harvests credentials for package registries, source-code platforms and cloud services — npm and PyPI tokens, GitHub and GitLab credentials, AWS keys, HashiCorp Vault tokens and SSH secrets — and sends them to infrastructure at skyleen[.]fr. What makes it more than another poisoned package is that sckit carries templates to install itself into npm packages, Python packages and GitHub Actions workflows, so every publishing credential it steals is a route to the next project: it is built to spread as a worm. Download counts have not been published, the affected packages sit in a fairly niche corner of the AI-agent tooling ecosystem, and no one has attributed the activity. It is the technique that matters to every software company: the same trick as the GHAPPIER case on this page, where a CI workflow rather than a person did the publishing, but this time with a payload designed to take the next maintainer’s tokens and repeat the process. A release workflow that can be steered by a commit is a publishing credential in its own right.

The Model Context Protocol project published advisory GHSA-qx49-fqc8-xw99 for its official Python SDK on 28 September. The SDK’s OAuth client did not validate the identity of the authorisation server or bind credentials to it, so an MCP server under an attacker’s control could redirect a client to an attacker-chosen token endpoint and receive the client secret, authorisation code and PKCE verifier. The advisory rates it High at CVSS 3.1 7.5; no CVE has been assigned. Users of ClientCredentialsOAuthProvider or PrivateKeyJWTOAuthProvider should also pass the new issuer= parameter, which becomes mandatory in 3.0. No exploitation has been reported. For teams wiring agents to third-party MCP servers, it is a reminder that the server on the other end is untrusted input, authentication included.
