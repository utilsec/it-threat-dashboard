Suspected Chinese state hackers used a BeyondTrust Remote Support zero-day from 29 August, stealing credentials and internal files

BeyondTrust and Google’s Mandiant and Threat Intelligence Group disclosed on 15 October that CVE-2026-102764 (CVSS v4 9.3), a flaw in how Remote Support validates the origin of internal messages, was exploited as a zero-day from 29 August against one BeyondTrust-hosted and one self-hosted appliance. Mandiant assesses the group, Armory Castle (also tracked as UNC5221 and Warp Panda), as Chinese and state-sponsored, and BeyondTrust calls it an espionage operation. The intruders planted a PHP web shell called Sawfly and a SOCKS5 tunneller called Bareclaw, gained root, collected the credentials the appliance stored and deleted logs, then used the support tool itself to reach endpoints and copy out documents such as software inventories. The fix shipped on 8 October and all SaaS instances were patched by 9 October; self-hosted customers without automatic updates must patch themselves. It leads because remote-support appliances hold privileged reach into customers’ and employees’ machines.

Ivanti Connect Secure: a three-flaw chain gave a new actor root on fully patched VPN appliances — one CVE is fixed and in KEV, the privilege-escalation link has no patch, and Ivanti’s integrity checker may miss it

Ivanti disclosed on 13 October that CVE-2026-104935 (CVSS v3.1 8.6), which covers an authentication bypass in welcome.cgi and a file write in wu.cgi, lets an unauthenticated attacker run commands on Connect Secure, and that it had been exploited against a limited number of customers. Volexity, which found it during an incident response opened on 5 October, says the attacker chained a third flaw — a privilege escalation in the dsinvoked broker — to reach root on an appliance running a fully patched 22.8R2.4; that third flaw has no CVE and no fix yet, and Ivanti expects to ship one in the coming weeks. Volexity dates its case to 3 October and Defused saw activity from 1 October, so exploitation goes back to at least early October. The actor, which Volexity tracks as UTA0576, left no web shell or backdoor: it ran commands through the exploit’s own HTTPS requests, stole LDAP and domain credentials, queried Active Directory for LAPS passwords and BitLocker keys, Kerberoasted, sprayed passwords, sniffed LDAP traffic and wiped Ivanti debug and Linux audit logs. Because the chain patches library code in memory and restores configuration data, Volexity and CISA warn that Ivanti’s Integrity Checker Tool may not detect it. CISA added CVE-2026-104935 to KEV on 13 October with a 16 October deadline, and watchTowr expects widespread, indiscriminate exploitation. Volexity has only low confidence that the motive is criminal rather than espionage. For technology companies Connect Secure is often the remote-access front door for engineers and administrators, and this actor went straight for the directory.

Citrix NetScaler: after three exploited zero-days, a fourth critical SAML flaw means some appliances patched in late September must be upgraded again

Citrix published bulletin CTX697191 on 8 October for CVE-2026-107406, a memory overflow in NetScaler ADC and Gateway rated CVSS v4 9.5 that Citrix says may lead to remote code execution or denial of service when the appliance acts as a SAML service provider or identity provider. Citrix says it is not aware of exploitation, Rapid7 says no successful exploitation has been publicly reported, and the flaw was not in KEV as of the 15 October catalog. The catch is the build history: appliances that took the late-September fixes (14.1-73.37 to 73.41, 13.1-64.23 to 64.28) are still exposed if they act as a SAML IdP, and older builds are exposed as SP or IdP, so many customers need a second upgrade in a fortnight; there is no workaround. CISA has urged Citrix customers to patch again and warns that attackers use CVE-2026-88779, the third zero-day (CVSS v4 8.7, in KEV since 4 October), to force reboots so that code planted through CVE-2026-88771 runs. That earlier pair, CVE-2026-88771 and CVE-2026-88772 (both CVSS v4 9.5, in KEV since 27 September), was exploited as zero-days from August: Google Threat Intelligence Group counts dozens of affected organisations across several industries in North America and Europe and attributes the activity only to suspected state-nexus actors, Arctic Wolf counts at least 78 organisations targeted, and Mandiant found two new malware families, the WHIPSHOT web shell and the SLAPSHOT tunneller, in attacks on CVE-2026-88772. Shadowserver saw more than 20,000 potentially vulnerable appliances when the attacks began, and Dutch hospitals briefly suspended patient portals as a precaution. For technology firms NetScaler is often the single sign-on and remote-access front door, and an appliance patched in October can still hold an intruder from August.

GhostAction returns: about 1,900 hijacked GitHub accounts pushed secret-stealing workflows into more than 30,000 repositories — and old, unrotated secrets were the target

GitGuardian reports that the GhostAction campaign came back on 8–9 October. Using stolen personal access tokens and credentials harvested by infostealers, the operators took over about 1,900 GitHub user accounts and pushed malicious workflow files with innocuous names such as security-audit.yml and github_actions_security.yml to more than 30,000 repositories belonging to about 3,000 users and organisations. The workflow searches git history for cloud keys, GitHub and GitLab tokens, npm, PyPI and Docker Hub publishing tokens and AI-provider API keys; the campaign tried to extract 3,174 secrets, and how many it actually obtained has not been published. The main spike hit 160 previously known victims and then about 28,000 new repositories 20 minutes later. GitHub began blocking the malicious workflow on 9 October, and further waves on 10 and 12 October extracted nothing. GitGuardian says the operators are counting on secrets never rotated after earlier GhostAction waves in September 2025 and August 2026, and some victims were hit again that way. No victims have been named. For software companies the lessons are that a leaked token stays useful until somebody revokes it, and that a workflow file pushed from a legitimate account looks like ordinary maintenance.

High Incident

FBI and Secret Service: the FortiBleed credential campaign against FortiGate firewalls and SSL VPNs is still active — there is no CVE to patch, and some owners have been locked out of their own devices

In a joint advisory dated 6 October, the FBI and the US Secret Service warned that attackers are still working through internet-facing Fortinet FortiGate firewalls and SSL VPN gateways with credentials obtained earlier. The campaign, first documented by SOCRadar and Hudson Rock in June, abuses reused or leaked passwords and legacy SHA-256 password storage rather than a software flaw: the operators spray and stuff credentials, crack extracted hashes offline and, according to researchers, run a sniffer that captures authentication traffic across 24 protocols. Some victims have been locked out after the attackers created administrator accounts of their own and changed or deleted the legitimate ones. SOCRadar’s count of more than 86,644 working device credentials in 194 countries dates from 19 June and is not a new tally; it says more than 430,000 FortiGates have been targeted and that it has confirmed at least 12 ransomware deployments from the access. The FBI links the access to Payload ransomware, and researchers describe a Russian-speaking access broker with overlaps to the INC and Lynx operations. The agencies say the targets span all 16 US critical-infrastructure sectors. For technology companies and MSPs that run FortiGates for themselves or for customers, a fully patched device with a reused password is still an open door.

DIVD’s breach came through two Zammad helpdesk zero-days that took the attacker from a hijacked session to root “in seconds” — both are now in CISA KEV, volunteer contact data got out, and DIVD tells every Zammad user to move to version 7

The Dutch Institute for Vulnerability Disclosure has published its case file on the breach it first announced on 24 September. The way in was a chain of two previously unknown flaws in the open-source Zammad helpdesk it ran: CVE-2026-102489, a session-fixation flaw that leads to code execution as the zammad user, and CVE-2026-102490, a local privilege escalation from that user to root. From there the attacker reached other services and read and exfiltrated data. DIVD says volunteer data got out, such as DIVD email addresses and possibly contact details, and that network segmentation stopped deeper access; its timeline puts the first malicious access on 21 September and detection on 22 September. DIVD maintains that an autonomous AI agent ran the attack, pointing to notes the agent left explaining its own decisions and describing the intrusion as loud and messy; that attribution is DIVD’s own assessment and has not been independently confirmed. CISA added both CVEs to the Known Exploited Vulnerabilities catalog on 2 October with a 5 October federal deadline. The CNA rates them CVSS v4 8.7 and 8.5, or 9.4 when chained; the code-execution flaw affects Zammad 6.3.0–6.5.4, and the privilege escalation reaches back to much older releases. “Plugin4Shell”: AI coding agents check out a pinned commit but never verify they got it — a branch named after the SHA installs attacker code; Claude Code and Codex are fixed, GitHub Copilot and Gemini CLI are not

Researchers Or Nevo, Dor Granat and Niv Hoffman of AIR Security published on 17 September a plugin-installation flaw shared by Claude Code, OpenAI Codex, GitHub Copilot and Google’s Gemini CLI. Each agent lets a plugin or extension be pinned to a commit SHA, and each installs it with a git checkout of that value — but git resolves a branch name before a commit hash, so an attacker who controls the plugin repository creates a branch named identically to the pinned SHA, makes it the default, and the checkout silently lands on attacker code while the pin appears to have been honoured. Background auto-update makes the attack zero-click for anyone who already installed the plugin. The researchers have a working proof of concept; no in-the-wild exploitation is claimed and no CVE is cited. The patch status is uneven and worth stating plainly, including for Anthropic’s own product: Claude Code was fixed in 2.1.179, confirmed on 17 June, and Codex in 0.146.0, verified on 12 August; GitHub Copilot has no fix; and Google says Gemini CLI is deprecated and will not be fixed, directing users to Antigravity. The class of bug is the one this page has watched all month: developer tooling that trusts a reference it did not verify, in a process that runs with the developer’s full credentials.
