Top Story

Attackers went global on VMware vCenter within days of the patch — 361 victim IPs across 47 countries, with reverse_ssh left behind on the virtualization control plane

A critical directory-traversal flaw in the VMware vCenter Server syslog service, CVE-2026-59310 (CVSS 9.8), gives an unauthenticated attacker remote code execution, and it is now being exploited at scale. Broadcom shipped fixes on 29 July 2026; DFIR firm QUIRSO recorded first contact with attacker-controlled infrastructure on 3 August, just five days later, and had counted 361 distinct victim IP addresses across 47 countries by 7 August, concentrated heavily in Germany, the United States, Turkey, Iran and France. The observed intrusion chain runs from path-traversal activity consistent with the flaw, to a malicious cron job for persistence, to deployment of the open-source reverse_ssh framework to hold a covert command-and-control channel. Researchers assess with moderate confidence that a suspected China-nexus operator is behind the activity and is dropping a Babuk-derived ransomware variant, which some believe functions as a smokescreen for deeper, quieter intrusion rather than as the actual goal — that attribution and motive are assessed, not confirmed. vCenter is the management plane for the virtualization estate: whoever controls it can typically reach every guest VM, every datastore and, in most environments, the backup infrastructure too, which is exactly why it is such a high-value target. The flaw is not yet listed in CISA's Known Exploited Vulnerabilities catalog as of this edition despite the scale of observed exploitation. Fixed builds are vCenter 9.1.0.0300, 9.0.2.0100, and the patched 8.0 U3 and U2 lines. Any organisation running an internet- or broadly-network-reachable vCenter instance that was not patched by early August should assume compromise is possible and hunt accordingly, not merely patch and move on.

The material at stake is engineering-grade product lifecycle data — drawings, test reports, facility photos and project plans — not typical customer PII, which raises the stakes for manufacturers and their supply chains specifically.

High Incident

A worm in the npm package keyv used stolen credentials to poison hundreds of packages within about 30 minutes

A supply-chain worm compromised the widely-used npm package keyv using stolen publishing credentials, then used that foothold to automatically poison hundreds of further packages in roughly half an hour, according to The Hacker News. The malicious versions harvested developer credentials, CI/CD tokens and cloud API keys from build environments, and in some cases planted hooks in editor or task-runner configuration that could trigger the payload later. The speed of propagation is the headline risk: automated dependency-poisoning worms can outrun manual detection and typical patch-review cycles, and any organisation that pulled affected package versions during the window should assume its build pipeline credentials may be compromised.

Medium Intel

Mustang Panda adds a signed kernel-mode rootkit to its CoolClient backdoor, hiding behind an expired 2013 certificate

Chinese state-linked espionage group Mustang Panda has added a signed Windows kernel-mode rootkit to its CoolClient backdoor, according to The Hacker News, using a code-signing certificate from 2013 that has since expired but which Windows will still load under older driver-signing rules. The rootkit hides malicious processes and network activity from standard monitoring tools, making the backdoor harder to detect once installed. The activity has been observed against government targets in Myanmar, Mongolia, Pakistan and Russia. The technique — abusing legacy signed drivers to run kernel-mode code — is not new, but its continued effectiveness is a reminder that driver-signing policy and allow-lists deserve periodic review rather than a one-time setup.

Active espionage campaign — observed against government targets in Myanmar, Mongolia, Pakistan and Russia Not a CVE-based technique
Mitigate via driver-signing policy, not a vendor patch Action: Government and defence-adjacent organisations, especially in the named regions, should enable Windows HVCI/driver-blocklist enforcement and review for legacy or expired signed drivers permitted to load in kernel mode. Hunt for CoolClient indicators in endpoint telemetry where available.

Microsoft’s August Patch Tuesday fixes 398 CVEs, including one exploited local elevation-of-privilege zero-day tied to a North Korean backdoor campaign

Microsoft’s August 2026 Patch Tuesday addressed 398 CVEs. Exactly one was under active exploitation at release: CVE-2026-68820, a use-after-free vulnerability in the Windows Ancillary Function Driver for WinSock (afd.sys), rated CVSS 7.0. It is a local elevation-of-privilege flaw — an attacker needs existing code execution on the machine to use it to gain higher privileges, not an unauthenticated remote entry point. Because this is a local-privilege-escalation bug, its danger is realized after an attacker has already landed via phishing or another initial-access method — which is exactly the Lazarus delivery chain observed here.
